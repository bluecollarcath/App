## Talking to the processor directly

Compilers write almost all embedded code, but every embedded engineer reads assembly: to debug a crash from a register dump, to check what the compiler did with a time-critical loop, to write startup code and interrupt entry, and to understand what "a function call" actually costs. We'll use **RISC-V** (RV32I), the open ISA from Lesson 1.1; ARM Cortex-M assembly looks very similar.

## Registers and the ABI

RV32I has 32 integer registers, each 32 bits. `x0` is hard-wired to zero. The **application binary interface** (ABI) gives the others names and roles that every compiler and library agrees on:

| Register | ABI name | Role | Saved by |
|---|---|---|---|
| x1 | `ra` | return address | caller |
| x2 | `sp` | stack pointer | callee |
| x10–x11 | `a0`–`a1` | arguments and return values | caller |
| x12–x17 | `a2`–`a7` | more arguments | caller |
| x5–x7, x28–x31 | `t0`–`t6` | temporaries | caller |
| x8–x9, x18–x27 | `s0`–`s11` | saved registers | callee |

"Saved by callee" means a function may use that register only if it restores the old value before returning; "saved by caller" means a function may freely overwrite it, so the caller must save it if it needs it later.

## Arithmetic, memory and branches

```asm
    addi t0, zero, 10      # t0 = 10
    add  t1, t0, t0        # t1 = 20
    slli t2, t1, 2         # t2 = t1 << 2 = 80 (multiply by 4)
    lw   t3, 0(a0)         # t3 = word at address a0
    sw   t3, 4(a0)         # store it at a0 + 4
    beq  t0, t1, done      # branch if equal
    blt  t0, t1, less      # branch if less than (signed)
```

There are no "if" or "for" instructions: control flow is just compares and branches.

## A loop

Sum an array of `n` 32-bit integers. On entry `a0` points to the array and `a1` holds `n`; the result goes back in `a0`:

```asm
sum:
    li   t0, 0             # t0 = running total
loop:
    beqz a1, end           # if n == 0, we're done
    lw   t1, 0(a0)         # load the next element
    add  t0, t0, t1        # total += element
    addi a0, a0, 4         # advance the pointer by 4 bytes
    addi a1, a1, -1        # n--
    j    loop
end:
    mv   a0, t0            # return value in a0
    ret                    # jump back to the address in ra
```

Each element costs 6 instructions. Compilers improve that by **unrolling** the loop (processing several elements per iteration) and removing the separate counter.

## The stack and function calls

`jal ra, func` (usually written `call func`) jumps to `func` and saves the return address in `ra`; `ret` jumps back. If a function calls another function, it must save its own `ra` first, along with any `s` registers it uses. Those go on the **stack**, a region of memory that grows **downward** from high addresses, with `sp` pointing to its top. The RISC-V ABI keeps `sp` 16-byte aligned.

```asm
func:
    addi sp, sp, -16       # prologue: allocate a 16-byte frame
    sw   ra, 12(sp)        # save return address
    sw   s0, 8(sp)         # save a callee-saved register we'll use
    # ... body: may call other functions, use s0 ...
    lw   s0, 8(sp)         # epilogue: restore
    lw   ra, 12(sp)
    addi sp, sp, 16        # free the frame
    ret
```

Local arrays live in the frame too, which is why a large local array on a microcontroller with a few kilobytes of stack causes a **stack overflow**: the stack grows down into other data, corrupting it silently. Embedded developers size stacks carefully and often fill them with a known pattern at startup to measure their high-water mark.

## Practice

```quiz
? The `sum` loop runs over a 10-element array. Counting the `li`, every loop instruction, the final `beqz` that exits, and `mv` and `ret`, how many instructions execute?
= 64 | 0.001 |
> 1 (`li`) + 10 × 6 (loop body including `j`) + 1 (exiting `beqz`) + 2 (`mv`, `ret`) = 64.
```

```quiz
? What value is in `t2` after `addi t0, zero, 3` and `slli t2, t0, 4`?
= 48 | 0.001 |
> $3 \ll 4 = 3 \times 16$.
```

```quiz
? A function saves `ra`, `s0`, `s1` and `s2` (4 bytes each) and must keep `sp` 16-byte aligned. How many bytes does its frame need?
= 16 | 0.001 | bytes
> 16 bytes of registers, already a multiple of 16.
```

```quiz
? A function must preserve which registers for its caller?
+ `sp` and the saved registers `s0`–`s11`
- the temporaries `t0`–`t6`
- the argument registers `a0`–`a7`
- every register
> Callee-saved registers must hold the same values on return.
```

```quiz
- is stored in registers
- is managed by hardware without software involvement
> Allocate by subtracting from `sp`.
```

## Key takeaways

- RV32I has 32 registers; the ABI defines `ra`, `sp`, arguments `a0`–`a7`, caller-saved `t`, callee-saved `s`.
- Control flow is compare-and-branch; loops are branches back to a label.
- Calls save the return address in `ra`; non-leaf functions save `ra` and used `s` registers in a stack frame.
- The stack grows downward; overflowing it silently corrupts memory.
