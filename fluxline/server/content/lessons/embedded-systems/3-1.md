## Moving bytes between chips

A microcontroller talks to sensors, memories, displays, radios and other processors over a few standard **serial** interfaces that send bits one at a time on a handful of wires. Three dominate: UART, SPI and I²C.

| | UART | SPI | I²C |
|---|---|---|---|
| Wires | TX, RX (+ GND) | SCLK, MOSI, MISO, CS per device | SCL, SDA (+ GND) |
| Clock | none (agreed baud rate) | from the controller | from the controller |
| Duplex | full | full | half |
| Devices | point to point | one controller, many targets (one CS each) | up to ~100 on two wires, by address |
| Typical speed | 9.6 kb/s – 1 Mb/s | 1–50+ MHz | 100 kHz, 400 kHz, 1 MHz |

## UART: asynchronous framing

A UART sends no clock. Both ends are configured for the same **baud rate**, and each byte is framed: the idle line is high, a **start bit** (low) marks the beginning, then 8 data bits **LSB first**, optionally a parity bit, then one or more **stop bits** (high).


With 8N1 framing (8 data bits, no parity, 1 stop bit), each byte takes 10 bit times, so 115,200 baud carries 11,520 bytes per second. The receiver detects the start edge, then samples each bit near its middle using its own clock. Since there's no shared clock, the two baud rates must agree within about ±2% over a frame, which is why UARTs prefer crystal clocks and "magic" rates like 115,200 that divide common crystal frequencies cleanly.

UART is the standard debug console, and it's the logic-level layer under RS-232 and RS-485 (which change only the voltage levels and add differential signaling for long cables).

## SPI: fast and simple

The controller drives a clock (**SCLK**), sends data on **MOSI** (controller out, target in) and simultaneously receives on **MISO**; a **chip select** (CS, active low) per target picks who's listening. Every clock shifts one bit each way, so it's full duplex with no addressing overhead. Four **modes** (CPOL, CPHA) set the clock's idle level and which edge samples data; controller and target must agree, and mismatched modes are the most common SPI bug.

> At 10 MHz, SPI moves 10 Mb/s = 1.25 MB/s, fast enough for flash memory, displays, SD cards and ADCs.

## I²C: two wires, many devices

**SCL** (clock) and **SDA** (data) are **open-drain** lines with pull-up resistors (Lesson 2.1), so any device can pull them low. A transaction starts with a **START** condition (SDA falls while SCL is high), then a 7-bit **address** and a read/write bit; the addressed device pulls SDA low to **ACK** each byte. Many sensors share one bus, each at its own address.

**Pull-up sizing.** The pull-ups and the bus capacitance $C_b$ set the rise time, $t_r \approx 0.85R_pC_b$. Fast mode (400 kHz) allows 300 ns, so

$$
R_p \le \frac{300\ \text{ns}}{0.85\,C_b}
$$

With 200 pF of bus capacitance, $R_p \le 1.8$ kΩ; too weak a pull-up (the "10 k because that's what was in the drawer") gives slow, rounded edges and intermittent failures. The minimum is set by the 3 mA sink limit: $R_p \ge 3.3\ \text{V}/3\ \text{mA} = 1.1$ kΩ at 3.3 V.


```quiz
= 2.95 | 0.005 | kΩ
> $10^{-6}/(0.8473 \times 4\times10^{-10}) = 2.95$ kΩ.
```

```quiz

+ a baud-rate mismatch between the two ends

- the wrong I²C address
- missing pull-up resistors on SPI
> Without a shared clock, both ends must agree on the bit rate.
```

```quiz

+ So that any device can pull the shared line low without fighting another device driving it high
- To make the bus faster
- To allow full-duplex transfers
- To remove the need for a ground wire
> The pull-ups provide the high level.
```

## Key takeaways

- UART: asynchronous, start/data/stop framing, 10 bits per byte for 8N1; baud rates must match within ~2%.
- SPI: clock + MOSI/MISO + chip select; fast, full duplex; match the mode (CPOL/CPHA).
- I²C: two open-drain wires, addressed devices, ACK per byte; size pull-ups for rise time ($R_p \le t_r/0.85C_b$).
