## Circuits that follow a plan

A **finite-state machine (FSM)** is a sequential circuit that moves between a fixed set of **states** based on its inputs, producing outputs as it goes. Traffic lights, vending machines, communication protocols, and every CPU's control unit are FSMs.

An FSM has three parts:
1. a **state register** (flip-flops) holding the current state,
2. **next-state logic** computing the next state from the current state and inputs,
3. **output logic**.

### Moore vs. Mealy

| | Moore | Mealy |
|---|---|---|
| Outputs depend on | the current state only | the current state **and** inputs |
| Output timing | changes only after a clock edge | can change as soon as inputs change |
| States needed | sometimes more | sometimes fewer |

Moore machines are easier to reason about and their outputs are glitch-free; Mealy machines can react one cycle sooner.

## The design process

1. Describe the behavior in words and draw a **state diagram**.
2. Write the **state table**.
3. Choose a **state encoding** (binary, one-hot, Gray).
4. Derive next-state and output equations (K-maps).
5. Build it, or write it in an HDL and let a tool do steps 4–5.

## Example: a "101" sequence detector

Design a Moore machine whose output $Z$ is 1 for one cycle after the input $x$ has shown the sequence 1, 0, 1. Overlaps count: in 10101 the detector fires twice.

The states record how much of the pattern we've seen:

```circuit
STATE 0,0 S0 Z=0 loop=0
STATE 3.2,0 S1 Z=0 loop=1
STATE 3.2,2.6 S2 Z=0
STATE 6.4,2.6 S3 Z=1 accept
ARROW 0.45,0 2.75,0 1 color=anno
ARROW 3.2,0.45 3.2,2.15 0 color=anno
ARROW 3.65,2.48 5.95,2.48 1 color=anno
ARROW 5.95,2.74 3.65,2.74 0
ARROW 6.05,2.32 3.55,0.28 1 side=-1
ARROW 2.85,2.32 0.35,0.28 0
caption: The 101 detector. S0: nothing matched; S1: saw 1; S2: saw 10; S3: saw 101, so $Z = 1$. Arrows are labeled with the input $x$.
```

| Current | $x = 0$ | $x = 1$ | $Z$ |
|---|---|---|---|
| S0 | S0 | S1 | 0 |
| S1 | S2 | S1 | 0 |
| S2 | S0 | S3 | 0 |
| S3 | S2 | S1 | 1 |

From S3, a 0 gives "10" (the end of 101 plus the new 0), so it goes to S2. That's what makes overlapping matches work.

**Encoding** S0 = 00, S1 = 01, S2 = 10, S3 = 11 with state bits $S_1S_0$, the K-maps give

$$
N_1 = S_0\overline{x} + S_1\overline{S_0}x, \qquad N_0 = x, \qquad Z = S_1S_0
$$

Two flip-flops and a handful of gates.

> **Trace** the input 1 1 0 1 0 1 1:
> states S1, S1, S2, S3 (Z = 1), S2, S3 (Z = 1), S1. Two detections, at the 4th and 6th inputs.

### Encoding choices

- **Binary**: fewest flip-flops, $\lceil\log_2 n\rceil$.
- **One-hot**: one flip-flop per state, simpler and faster next-state logic. Preferred on FPGAs, where flip-flops are plentiful.

## Key takeaways

- FSM = state register + next-state logic + output logic.
- Moore outputs depend on state only; Mealy outputs also depend on inputs.
- Design flow: diagram → table → encoding → equations. Binary uses $\lceil\log_2 n\rceil$ flip-flops; one-hot uses $n$.
