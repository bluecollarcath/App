## Gates aren't instant

Boolean algebra assumes outputs change the instant inputs do. Real gates take time, typically tens of picoseconds in a modern chip and nanoseconds in discrete logic. Timing determines how fast a circuit can run, and it can produce brief wrong outputs called **glitches**.

## Propagation and contamination delay

- **Propagation delay** $t_{pd}$: the *longest* time from an input change until the output is stable at its new value.
- **Contamination delay** $t_{cd}$: the *shortest* time from an input change until the output starts to change.

Delays add along a path. The **critical path** is the slowest path from any input to any output, and it sets the circuit's speed.

> **Example.** A path goes through a NOT (30 ps), a NAND (40 ps), and an OR (50 ps): $t_{pd} = 120$ ps. If a different path through the same circuit takes 150 ps, *that* is the critical path, and the circuit needs 150 ps to settle.

In a synchronous system, a clock period must cover the critical path plus flip-flop overhead (next unit), so

$$
f_{max} = \frac{1}{t_{\text{critical path}} + \text{overhead}}
$$

> If the logic takes 6 ns in total, $f_{max} = 1/6\ \text{ns} = 167$ MHz.

## Glitches and hazards

A **hazard** is a possible momentary wrong output caused by unequal path delays. Consider

$$
F = AB + \overline{A}C
$$

with $B = C = 1$. Logically $F = A + \overline{A} = 1$ no matter what $A$ does. But when $A$ falls from 1 to 0, the $AB$ term turns off right away, while $\overline{A}C$ must wait for the inverter. For a moment both terms are 0, and $F$ glitches low.

vline: 4, glitch
caption: With each gate taking one delay unit, $AB$ falls before $\overline{A}C$ rises, so $F$ briefly drops to 0: a static-1 hazard.
```

This is a **static-1 hazard**: the output should stay 1 but momentarily drops. The fix is to add the **consensus term** $BC$, which covers the transition:

$$
F = AB + \overline{A}C + BC
$$

Logically it's redundant, but it holds $F = 1$ while $A$ changes. On a K-map, a hazard appears wherever two adjacent groups don't overlap; adding a group that bridges them removes it.

**Do glitches matter?** In synchronous designs, usually not: outputs are only sampled at clock edges, after everything has settled. They do matter for signals that act immediately: asynchronous resets, clock enables built from logic, and anything driving external hardware.

```

```quiz
? Why are glitches on combinational outputs usually harmless in a synchronous design?
+ Outputs are sampled only at clock edges, after the logic has settled

- Glitches cannot occur when a clock is present
- Flip-flops amplify glitches into valid signals
> As long as the clock period covers the critical path, the glitch is over before the next edge.
```

## Key takeaways

- $t_{pd}$ is the worst-case delay; the critical path sets the maximum clock speed.
- Unequal path delays cause glitches (hazards); a consensus term fixes a static-1 hazard.
- Synchronous design sidesteps most glitches by sampling only at clock edges.
