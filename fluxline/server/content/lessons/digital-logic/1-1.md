## Positional number systems

A number in base $b$ with digits $d_{n-1}\ldots d_1 d_0$ has value

$$
N = \sum_{k=0}^{n-1} d_k\, b^k
$$

Digital hardware uses **binary** (base 2) because a transistor switch is naturally two-state. **Hexadecimal** (base 16, digits 0–9, A–F) is shorthand: each hex digit is exactly four bits.

> $1011\,0110_2 = 128 + 32 + 16 + 4 + 2 = 182_{10} = \text{B6}_{16}$

**Decimal → binary:** repeatedly divide by 2 and read the remainders bottom-up, or subtract the largest powers of 2.

## Unsigned range

An $n$-bit unsigned number ranges from $0$ to $2^n - 1$. An 8-bit byte holds 0–255; a 16-bit ADC result holds 0–65,535.

## Signed numbers: two's complement

Every modern processor represents signed integers in **two's complement**. The most significant bit has *negative* weight:

$$
N = -d_{n-1}2^{n-1} + \sum_{k=0}^{n-2} d_k 2^k
$$

Range: $-2^{n-1}$ to $2^{n-1} - 1$ (8 bits: −128 to +127).

**To negate:** invert every bit and add 1.

> $+45 = 0010\,1101$. Invert: $1101\,0010$. Add 1: $1101\,0011 = \text{D3}_{16}$, which is $-45$.
> Check: $-128 + 64 + 16 + 2 + 1 = -45$. ✓

Why two's complement wins: **the same adder circuit** handles signed and unsigned addition, and subtraction is just addition of the negation. There is only one representation of zero.

## Overflow

Adding two $n$-bit numbers can produce a result that does not fit:

- **Unsigned overflow**: a carry out of the MSB.
- **Signed overflow**: adding two numbers of the same sign gives a result of the opposite sign. Adding numbers of opposite sign can *never* overflow.

> $0111\,1111 + 0000\,0001 = 1000\,0000$: $127 + 1$ "equals" $-128$ in 8-bit signed arithmetic.

**Sign extension**: to widen a two's-complement number, copy the sign bit into the new bits ($1101 \to 1111\,1101$, both $-3$).

## Key takeaways

- One hex digit = four bits.
- Two's complement: MSB weight is $-2^{n-1}$; negate by invert-and-add-one.
- Signed overflow occurs only when same-sign operands produce an opposite-sign result.
