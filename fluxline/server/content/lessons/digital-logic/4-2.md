## Clocked logic in Verilog

Sequential logic lives in `always` blocks triggered by a clock edge. A D flip-flop with a synchronous reset:

```verilog
module dff (
  input  wire clk, rst, d,
  output reg  q
);
  always @(posedge clk) begin
    if (rst) q <= 1'b0;
    else     q <= d;
  end
endmodule
```

For an **asynchronous** reset, add it to the sensitivity list: `always @(posedge clk or posedge rst)`.

### Blocking vs. non-blocking assignment

| | `=` (blocking) | `<=` (non-blocking) |
|---|---|---|
| Use in | combinational `always @(*)` | clocked `always @(posedge clk)` |
| Behavior | updates immediately, in order | all right-hand sides are read first, then everything updates together at the edge |

Non-blocking assignment models real flip-flops, which all sample at the same instant. This shift register is correct *because* of `<=`:

```verilog
always @(posedge clk) begin
  q1 <= d;
  q2 <= q1;   // gets the OLD q1: a true two-stage shift
end
```

With `=`, `q2` would receive the *new* `q1`, and the two stages would collapse into one. **Rule: `<=` in clocked blocks, `=` in combinational blocks, and never mix them in one block.**

## A counter

```verilog
module counter #(parameter N = 8) (
  input  wire         clk, rst, en,
  output reg  [N-1:0] count
);
  always @(posedge clk)
    if (rst)     count <= 0;
    else if (en) count <= count + 1;   // wraps from 2^N - 1 to 0
endmodule
```

The `parameter` makes the width configurable when the module is instantiated.

## An FSM: the 101 detector

The standard pattern uses one clocked block for the state register and one combinational block for the next-state logic:

```verilog
module detect101 (input wire clk, rst, x, output wire z);
  localparam S0 = 2'd0, S1 = 2'd1, S2 = 2'd2, S3 = 2'd3;
  reg [1:0] state, next;

  always @(posedge clk)                    // state register
    state <= rst ? S0 : next;

  always @(*) begin                        // next-state logic
    case (state)
      S0: next = x ? S1 : S0;
      S1: next = x ? S1 : S2;
      S2: next = x ? S3 : S0;
      S3: next = x ? S1 : S2;
      default: next = S0;
    endcase
  end

  assign z = (state == S3);                // Moore output
endmodule
```

## Testbenches

A **testbench** is a Verilog module with no ports that drives inputs and checks outputs in simulation:

```verilog
initial begin
  rst = 1; x = 0; #20 rst = 0;
  x = 1; #10 x = 0; #10 x = 1; #10;   // apply 1, 0, 1
  if (z !== 1) $display("FAIL: expected z = 1");
end
always #5 clk = ~clk;                 // 100 MHz clock (10 ns period)
```

Free simulators: Icarus Verilog with GTKWave for waveforms, and Verilator.

## FPGAs

A **field-programmable gate array** is a chip of configurable logic you program with your HDL design:

- **LUTs (lookup tables)**: small memories that implement any function of their inputs. A 6-input LUT stores $2^6 = 64$ bits, one output value per input combination.
- **Flip-flops** next to every LUT.
- **Programmable routing** between them.
- Hard blocks: **block RAM**, **DSP multipliers**, high-speed transceivers, sometimes whole CPUs.

The toolchain flows **synthesis → place and route → timing analysis → bitstream**. Timing analysis reports whether every register-to-register path meets the clock period, exactly the inequality from Lesson 3.1. Popular beginner boards use Lattice iCE40 (with the open-source Yosys/nextpnr tools), AMD/Xilinx Artix-7, or Intel/Altera Cyclone.

## Key takeaways

- `always @(posedge clk)` with `<=` for flip-flops; `always @(*)` with `=` for combinational logic.
- FSMs: a clocked state register plus a combinational next-state block.
- Testbenches verify designs in simulation; FPGAs implement them with LUTs, flip-flops, and routing.
