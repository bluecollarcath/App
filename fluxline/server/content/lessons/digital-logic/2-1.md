## Building blocks for routing data

Combinational logic means outputs depend only on the *current* inputs, with no memory. Beyond individual gates, a few standard blocks appear in nearly every digital system: multiplexers choose, decoders select, and encoders compress.

## Multiplexers

A **multiplexer (MUX)** is a digitally controlled switch: select lines choose which data input reaches the output.

```circuit
T 0.4,-0.5 I_0
W 0.4,-0.5 1,-0.5
T 0.4,0.5 I_1
W 0.4,0.5 1,0.5
MUX 2,0
W 3,0 3.6,0
T 3.6,0 Y
T 2,1.9 S
W 2,1.3 2,1.9
caption: A 2-to-1 multiplexer: $Y = I_0$ when $S = 0$ and $Y = I_1$ when $S = 1$.
```

$$
Y = \overline{S}\,I_0 + S\,I_1
$$

A $2^n$-to-1 MUX has $n$ select lines. A 4-to-1 MUX: $Y = \overline{S_1}\,\overline{S_0}I_0 + \overline{S_1}S_0I_1 + S_1\overline{S_0}I_2 + S_1S_0I_3$.

**Uses:** choosing between data sources (ALU inputs, bus sharing), and parallel-to-serial conversion. MUXes are also the basic building blocks of FPGAs.

### Implementing any function with a MUX

A $2^n$-to-1 MUX can implement **any** $n$-variable function: connect the variables to the select lines and wire each data input to the truth-table value (0 or 1). Even better, a $2^{n-1}$-to-1 MUX is enough if you feed the last variable (or its complement) into the data inputs.

> **Example.** Implement $F(A, B, C) = \sum m(1, 2, 6, 7)$ with a 4-to-1 MUX, using $A, B$ as the select lines.
>
> For each value of $AB$, look at the two rows ($C = 0, 1$):
>
> | $AB$ | $F$ when $C=0$ | $F$ when $C=1$ | Data input |
> |---|---|---|---|
> | 00 | 0 | 1 | $I_0 = C$ |
> | 01 | 1 | 0 | $I_1 = \overline{C}$ |
> | 10 | 0 | 0 | $I_2 = 0$ |
> | 11 | 1 | 1 | $I_3 = 1$ |

## Decoders

An **$n$-to-$2^n$ decoder** activates exactly one of its $2^n$ outputs, the one whose number matches the binary input. A 3-to-8 decoder with input 101 drives output $Y_5$ high and all others low.

**Uses:** memory address decoding (selecting one chip or one row), instruction decoding in CPUs, and driving displays. Because each output is one minterm, **a decoder plus an OR gate implements any SOP function**: OR together the outputs for the function's minterms.

## Encoders and priority encoders

An **encoder** does the reverse, converting a one-hot input to its binary index. If more than one input can be active (for example, several interrupt requests at once), use a **priority encoder**, which reports the highest-numbered active input plus a *valid* bit that says whether any input is active at all.

| $I_3$ | $I_2$ | $I_1$ | $I_0$ | $Y_1Y_0$ | Valid |
|---|---|---|---|---|---|
| 0 | 0 | 0 | 0 | xx | 0 |
| 0 | 0 | 0 | 1 | 00 | 1 |
| 0 | 0 | 1 | x | 01 | 1 |
| 0 | 1 | x | x | 10 | 1 |
| 1 | x | x | x | 11 | 1 |

## Key takeaways

- MUX: select lines choose an input; $2^n$-to-1 needs $n$ selects and can implement any $n$-variable function.
- Decoder: one output per minterm; decoder + OR = any SOP function.
- Priority encoder: index of the highest active input, plus a valid flag.
