## Adding redundancy on purpose

Shannon proved that clever coding can get almost error-free communication at rates up to capacity. **Error-control coding** adds carefully structured redundancy, so the receiver can detect, and often correct, errors without retransmission. Every modern link uses it: Wi-Fi and 5G (LDPC and polar codes), CDs and QR codes (Reed–Solomon), deep-space probes (convolutional and turbo codes), and DRAM (Hamming codes, as ECC memory).

## Block codes

An $(n, k)$ block code maps each block of $k$ data bits to an $n$-bit **codeword**, adding $n - k$ check bits. Its **code rate** is $r = k/n$: the fraction of transmitted bits that carry data.

The key property is the **minimum Hamming distance** $d_{min}$: the fewest bit positions in which any two codewords differ. A code with distance $d_{min}$ can

- **detect** up to $d_{min} - 1$ errors, or
- **correct** up to $t = \left\lfloor\dfrac{d_{min} - 1}{2}\right\rfloor$ errors,

because a received word with $t$ or fewer errors is still closer to the right codeword than to any other.

> **Single parity bit** ($n = k + 1$, $d_{min} = 2$): detects any single error, corrects none.
>
> **Repetition code** (3, 1): send each bit three times and take a majority vote. $d_{min} = 3$, corrects one error. With raw error probability $p = 0.01$, the decoded error rate is $3p^2(1 - p) + p^3 = 3\times10^{-4}$, 33 times better, at the cost of a rate of only 1/3.

## Hamming codes

The (7, 4) **Hamming code** is far more efficient: 3 parity bits protect 4 data bits ($r = 4/7$), with $d_{min} = 3$, so it corrects any single error. Each parity bit checks a different subset of the bit positions. At the receiver, recomputing the checks gives a 3-bit **syndrome**:

- syndrome 000: no error detected;
- any other value: it's the **binary position** of the flipped bit, so flip it back.

Hamming codes exist for every $n = 2^m - 1$: (7, 4), (15, 11), (31, 26)... with $m$ check bits each. Adding one overall parity bit (SECDED) corrects single errors and detects double errors, the standard for ECC memory.

## Convolutional codes and Viterbi decoding

Instead of blocks, a **convolutional encoder** passes the bit stream through a short shift register and outputs several modulo-2 sums for each input bit (rate 1/2 is typical). Its output depends on the current bit and a few previous ones, so the redundancy is spread through the stream. The **Viterbi algorithm** finds the most likely transmitted sequence efficiently by tracking the best path through a trellis of encoder states. It was the workhorse of satellite links, 2G/3G cellular and early Wi-Fi.

## Approaching capacity: turbo, LDPC and polar codes

Modern codes come within a fraction of a dB of the Shannon limit:

- **Turbo codes** (1993): two convolutional codes with an interleaver between them, decoded iteratively. 3G/4G, deep space.
- **LDPC codes** (Gallager, 1960; rediscovered in the 1990s): very long block codes with sparse parity-check matrices, decoded by iterative message passing. Wi-Fi 6, 5G data channels, DVB-S2, 10GBASE-T Ethernet.
- **Polar codes** (2009): the first codes provably reaching capacity; used for 5G control channels.

The benefit is measured as **coding gain**: the reduction in $E_b/N_0$ needed for a target error rate. A good LDPC code needs about 1–2 dB for $P_b = 10^{-5}$ instead of uncoded BPSK's 9.6 dB: a coding gain near 8 dB, worth a sixfold increase in range or power savings.

## Key takeaways

- An $(n, k)$ code has rate $k/n$; it detects $d_{min} - 1$ errors or corrects $\lfloor(d_{min} - 1)/2\rfloor$.
- Hamming codes ($n = 2^m - 1$) correct one error via the syndrome; SECDED adds double-error detection.
- Convolutional codes with Viterbi decoding; turbo, LDPC and polar codes approach the Shannon limit.
- Coding gain is the $E_b/N_0$ saved for a target error rate.
