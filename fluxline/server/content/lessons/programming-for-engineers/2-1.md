## Why C?

Python is ideal for analysis, but it can't run on a \$1 microcontroller with 8 KB of RAM, and it can't guarantee that an interrupt handler finishes in 2 µs. **C** compiles directly to machine instructions, gives you control over every byte of memory, and runs everywhere: microcontroller firmware, operating-system kernels, device drivers, DSP code, and the internals of Python itself. Embedded Systems (Unit 2) is written in C.

## From source to executable

```c
#include <stdio.h>

int main(void) {
    double r_top = 10e3, r_bottom = 5e3, v_in = 9.0;
    double v_out = v_in * r_bottom / (r_top + r_bottom);
    printf("Vout = %.2f V\n", v_out);   /* prints: Vout = 3.00 V */
    return 0;
}
```

```bash
gcc -Wall -Wextra -O2 -o divider divider.c   # compile and link
./divider                                    # run
```

Building happens in stages: the **preprocessor** expands `#include` and `#define`, the **compiler** turns C into assembly and object code, and the **linker** joins object files and libraries into an executable. For a microcontroller, a **cross-compiler** (such as `arm-none-eabi-gcc`) produces code for the target chip instead of your PC. Always compile with warnings on (`-Wall -Wextra`): most of what they flag is a real bug.

## Types and sizes

C's basic types have sizes that depend on the platform: an `int` is 16 bits on some microcontrollers and 32 on a PC. Embedded code therefore uses the **fixed-width types** from `<stdint.h>`:

| Type | Size | Range |
|---|---|---|
| `uint8_t` / `int8_t` | 8 bits | 0–255 / −128–127 |
| `uint16_t` / `int16_t` | 16 bits | 0–65535 / −32768–32767 |
| `uint32_t` / `int32_t` | 32 bits | 0–4.29×10⁹ / ±2.1×10⁹ |
| `float` / `double` | 32 / 64 bits | ~7 / ~16 significant digits |

**Integer overflow** wraps around for unsigned types: a `uint8_t` holding 255, plus 1, becomes 0. A 16-bit timer counting microseconds overflows every 65.5 ms, a classic embedded bug. (Signed overflow is undefined behavior in C: the compiler may do anything.)

## Integer arithmetic traps

```c
int a = 7, b = 2;
double x = a / b;          /* 3.0, not 3.5: integer division happens first */
double y = (double)a / b;  /* 3.5: cast first */
int pct = 1023 * 100 / 4096;   /* 24: multiply before dividing to keep precision */
```

Many microcontrollers have no floating-point hardware, so firmware often uses **fixed-point** integer math (DSP, Lesson 3.3): an ADC reading of 1023 out of 4095 at 3.3 V is `(uint32_t)reading * 3300 / 4095` millivolts, with no floats at all.

## Control flow and functions

```c
for (int k = 0; k < 8; k++) { /* ... */ }
while (!(STATUS_REG & READY)) { }   /* busy-wait (with care) */
switch (state) {
    case IDLE:    start(); state = RUN; break;
    case RUN:     if (done()) state = IDLE; break;
    default:      state = IDLE;
}

static inline uint16_t adc_to_mv(uint16_t counts) {
    return (uint32_t)counts * 3300u / 4095u;
}
```

C passes arguments **by value** (functions get copies); to let a function modify a caller's variable, pass a pointer (next lesson).

## Key takeaways

- C compiles to machine code: preprocess, compile, link; cross-compile for microcontrollers; always enable warnings.
- Use `<stdint.h>` fixed-width types; unsigned overflow wraps, signed overflow is undefined.
- Integer division truncates; cast or reorder operations; fixed-point math avoids floats.
- Arguments are passed by value.
