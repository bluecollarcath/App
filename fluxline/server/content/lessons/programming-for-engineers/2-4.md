## Grouping related data: structs

A **struct** bundles related values of different types into one object:

```c
#include <stdint.h>

typedef struct {
    uint16_t raw;          /* last ADC reading        */
    float    gain;         /* calibration: units/count */
    float    offset;
    char     name[16];
} sensor_t;

sensor_t temp = { .raw = 0, .gain = 0.0806f, .offset = -50.0f, .name = "TMP36" };

float sensor_value(const sensor_t *s) {        /* pass a pointer: no copy */
    return s->raw * s->gain + s->offset;        /* -> accesses members through a pointer */
}
```

`typedef` gives the struct a short name; `s->field` is shorthand for `(*s).field`. Pass structs by pointer (with `const` if the function won't modify them) to avoid copying.

**Padding.** The compiler may insert gaps between members so each is aligned to its natural boundary, so `sizeof` a struct can exceed the sum of its members. Order members from largest to smallest to minimize waste, and never assume a struct's memory layout matches a hardware register map or a file format unless you've checked it (or used compiler packing attributes).

## Splitting code into modules

Real firmware is many files. Each **module** has:

- a **header** (`.h`) declaring its public interface: types, function prototypes, constants;
- a **source** file (`.c`) implementing it.

```c
/* adc.h */
#ifndef ADC_H              /* include guard: prevents double inclusion */
#define ADC_H
#include <stdint.h>
void     adc_init(void);
uint16_t adc_read(uint8_t channel);
#endif
```

```c
/* adc.c */
#include "adc.h"
static uint8_t initialized;            /* static: private to this file */
void adc_init(void) { /* configure registers */ initialized = 1; }
uint16_t adc_read(uint8_t channel) { /* start conversion, wait, return result */ return 0; }
```

- `static` at file scope hides a variable or function from other files: use it for everything that isn't part of the interface.
- `extern` declares a variable defined in another file (use sparingly; global variables couple modules together).

## Building with make

A **Makefile** records how to build the program and rebuilds only what changed:

```make
CC      = gcc
CFLAGS  = -Wall -Wextra -O2
OBJS    = main.o adc.o filter.o

app: $(OBJS)
	$(CC) $(CFLAGS) -o app $(OBJS)

%.o: %.c
	$(CC) $(CFLAGS) -c $<

clean:
	rm -f app $(OBJS)
```

Each rule says: to make the target (left of the colon), you need the prerequisites (right), using the recipe (the indented line, which must start with a **tab**). Larger projects use CMake, which generates build files for any toolchain, and microcontroller vendors' IDEs generate makefiles behind the scenes.

## Files

On a PC (or a device with a file system), standard I/O reads and writes files:

```c
#include <stdio.h>

FILE *f = fopen("log.csv", "w");
if (f == NULL) { perror("fopen"); return 1; }
fprintf(f, "time_ms,voltage\n");
for (int k = 0; k < 100; k++)
    fprintf(f, "%d,%.3f\n", k, read_voltage());
fclose(f);
```

Always check that `fopen` succeeded, and always `fclose`. Reading uses `fgets` (a line at a time) and `sscanf` or `strtol` to parse. A logger that writes CSV in C and a Python script that plots it (Lesson 1.3) is a very common engineering workflow.

## Key takeaways

- Structs group related data; access with `.` or `->`; pass by `const` pointer; beware padding.
- Modules: `.h` interface with include guards, `.c` implementation, `static` for private items.
- `make` rebuilds only what changed; recipes start with a tab.
- File I/O: `fopen` (check it!), `fprintf`/`fgets`, `fclose`.
