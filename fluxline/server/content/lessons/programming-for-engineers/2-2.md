## Memory is a numbered list of bytes

Every variable lives at an **address**. A **pointer** is a variable that holds an address. Pointers are C's most powerful and most dangerous feature: they let functions modify their caller's data, give fast access to arrays and buffers, and let firmware talk to hardware registers at fixed addresses.

```c
int x = 42;
int *p = &x;      /* & takes the address of x; p "points to" x */
*p = 7;           /* * dereferences: writes 7 into x */
printf("%d\n", x);   /* 7 */
```

## Passing by reference

C passes arguments by value, so to change a caller's variables, pass their addresses:

```c
void swap(int *a, int *b) {
    int t = *a; *a = *b; *b = t;
}
int m = 1, n = 2;
swap(&m, &n);     /* m = 2, n = 1 */
```

Functions also use pointers to "return" several results, and to avoid copying large structures.

## Arrays and pointer arithmetic

An array is a contiguous block of elements, and its name acts as a pointer to the first element:

```c
uint16_t samples[8] = {10, 20, 30, 40, 50, 60, 70, 80};
uint16_t *s = samples;      /* same as &samples[0] */
s[2];                       /* 30 */
*(s + 2);                   /* 30: s + 2 moves 2 *elements* (4 bytes), not 2 bytes */
```

Pointer arithmetic counts in **elements**: adding 1 to a `uint32_t *` advances 4 bytes. C does **no bounds checking**: `samples[8]` silently reads or overwrites whatever comes next in memory. Writing past the end of a buffer (a **buffer overflow**) is the most common bug in C and the root of countless security holes.

Strings are `char` arrays ending in a zero byte (`'\0'`); forgetting room for that terminator is another classic overflow.

## Stack and heap

| | Stack | Heap |
|---|---|---|
| Holds | local variables, function arguments, return addresses | memory requested at run time |
| Lifetime | until the function returns | until you `free` it |
| Managed | automatically | manually: `malloc` / `free` |
| Size | small (often 1–8 KB on an MCU) | whatever's left |

```c
float *buf = malloc(1024 * sizeof(float));   /* request heap memory */
if (buf == NULL) { /* out of memory: handle it! */ }
/* ... use buf[0] .. buf[1023] ... */
free(buf);            /* give it back */
buf = NULL;           /* avoid using it by accident */
```

Heap bugs: **leaks** (forgetting `free`, so memory slowly runs out), **use-after-free** (touching memory after freeing it) and **double free**. Never return a pointer to a local (stack) variable: it vanishes when the function returns.

Many embedded and safety-critical coding standards (MISRA C, NASA's "Power of Ten") **forbid** `malloc` after initialization: on a device with little RAM that must run for years, fragmentation and allocation failures are unacceptable. Firmware uses statically allocated buffers sized at compile time.

## Pointers to hardware

On a microcontroller, peripheral registers are memory addresses (Embedded Systems, Lesson 2.1). A pointer to a fixed address reaches the hardware directly:

```c
#define GPIOA_ODR (*(volatile uint32_t *)0x48000014u)
GPIOA_ODR |= (1u << 5);   /* set pin 5 high */
```

`volatile` tells the compiler that the location can change or have side effects on its own, so every read and write must really happen.

```quiz
? `int a[5] = {4, 8, 15, 16, 23}; int *p = a + 1;` What is `*(p + 2)`?
= 16 | 0.001 |
> `p` points to `a[1]`; `p + 2` points to `a[3]`.
```

```quiz
? A `uint32_t *q` holds address 0x1000. What address does `q + 3` hold (in decimal)?
= 4108 | 0.001 |
> $4096 + 3 \times 4$.
```

```quiz
? How many bytes must a `char` array have to store the string "ADC" safely?
= 4 | 0.001 | bytes
> Three characters plus the terminating `'\0'`.
```

```quiz
? After `int x = 5; int *p = &x; *p += 3;` what is `x`?
= 8 | 0.001 |
> Writing through the pointer changes `x`.
```

```quiz
? What is wrong with a function that returns the address of one of its local variables?
+ The local variable lives on the stack and disappears when the function returns
- Local variables have no address
- Functions can't return pointers
- The pointer will always be NULL
> The caller is left with a dangling pointer.
```

```quiz
? Why do many embedded coding standards forbid `malloc` after startup?
+ Fragmentation and allocation failure are unacceptable on long-running, memory-limited devices
- `malloc` is slower than `printf`
- Microcontrollers have no RAM
- `malloc` only works on 64-bit processors
> Static allocation makes memory use predictable.
```

## Key takeaways

- `&` gives an address, `*` dereferences; pass pointers to let functions modify caller data.
- Arrays decay to pointers; pointer arithmetic counts elements; C never checks bounds.
- Stack: automatic, short-lived. Heap: `malloc`/`free`, with leaks, use-after-free and fragmentation risks.
- Hardware registers are reached through `volatile` pointers to fixed addresses.
